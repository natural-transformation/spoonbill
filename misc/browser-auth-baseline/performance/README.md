# Browser authentication measurement contract

This directory prepares Phase 0 of the browser authentication plan. It contains
**no collected performance evidence and no accepted reference operation budgets**.
`manifest.json` is deliberately `awaiting-reference-review`. The analyzer returns
`inconclusive` and exits nonzero until the reference is reviewed, its identities
and completed-work contracts are frozen, every measured budget is supplied, and
complete comparable evidence exists. Do not change this status to make a test or
release job green.

The [PostgreSQL wire proxy](postgres-wire-proxy.md) supplies bounded observation
of actual sequential v3 synchronization exchanges. Its physical-engine test is
separate from the no-PostgreSQL test glob; JDBC driver/workload mapping remains
pending, and its existence does not fill the manifest's measured budgets.

[Profiling capability notes](profiling.md) distinguish validated retained-heap
sensors, Linux-only native allocation/RSS probes, and the still-unavailable
cumulative JavaScript allocation counter. Tool installation never substitutes
one memory quantity for another or satisfies missing workload evidence.

The manifest enumerates 94 workload cells rather than discovering workloads from
whatever a collector happens to supply. Dimensions include both pinned baselines,
unused-feature paths, anonymous/authenticated setup, cold/warm and view variants,
password/challenge and short/representative proofs, policy/size/contention sweeps,
reconnect/failure/retention paths, separate node reads and snapshots, historical
transport, official Pekko transport, and Chromium/WebKit reference flows.
Default work counts and dimensions are in `protocol.defaultPasses` and
`protocol.defaultDimensions`; cell overrides are explicit. `completedWork(manifest,
cell, pass)`, `dimensions(manifest, cell)`, and `requiredMetrics(manifest, cell)`
resolve the exact counts, dimensions and shared metric set a runner must use.
Historical echo cells retain 40,000 total warmup messages and 10,000 measured
messages per connection. Historical core retains 10,000/5,000 operations.

Application client accounting is a required deterministic budget: handwritten
authentication lines/modules, generated bytes, emitted/minified/gzip/Brotli sizes
for authentication and application bundles, and HTTP/WebSocket exchanges. Reference
applications require zero custom authentication JavaScript and zero new client
domain-policy branches. Client inventory and emitted output hashes are provenance,
not proof that a source-language conversion removed delivered JavaScript.

## Review and collection prerequisites

Before freezing the manifest:

1. Complete and review the equivalent v3 reference, including challenge binding,
   logout/revocation, scoped outer settlement and durable delivery recovery.
   Record its immutable integration hash under each applicable baseline.
2. Specify and hash each cell's useful completed-work assertions. Capacity cells
   must exercise all listed limits; missing behavior cannot be represented by a
   faster but weaker collector.
3. Measure reference operation and metadata ceilings, and fill **every** required
   key in each cell's `operationCeilings` and `resourceCeilings`. These fields are
   currently null. Fixed zero rules in the global schemas cannot be overridden.
   API executions are not protocol round trips; an absent wire collector is a
   missing measurement, never an assumed equality with statement count.
4. Validate all collectors, supported browser sensors, useful-work counters,
   cold-child-process handling, heap/retention/native protocols and sensor
   resolution probes. Default 10 ms sampling is not by itself proof of an exact
   peak: the collector must validate peak coverage/error with its JFR/GC evidence
   or report the metric unsupported. Keep invasive profiling in memory passes.
5. Run baseline-only calibration on controlled hardware. The proposed numerical
   stability/precision limits and work counts can be revised **before candidate
   observations** with a recorded reason; preserve the prior protocol and raw
   records. Freeze the resulting manifest hash, review identity and timestamp.

These are concrete missing inputs, not instructions to invent favorable budgets.
No browser infrastructure failure is claimed: the existing native-browser gate
and the proposed performance collectors are different checks.

## Evidence shape

Comparison and calibration are separate JSONL files. Each has one `metadata`
record, `sample` records, then exactly one `completion` record with the observation
count. Truncation or any `failure` record makes the collection inconclusive. Keep
raw stdout, stderr and failed runs separately; never delete a failed pair and
substitute a favorable run inside an existing collection.

Metadata contains:

- `mode`, `manifestSha256`, `startedAt`, and `durationSeconds`.
- `provenance.baselines.feature`, `provenance.baselines.historical`, and
  `provenance.candidate`. Each has `gitCommit`, `dirtyDiffSha256`, `artifactSha256`,
  `referenceIntegrationSha256`, `flakeSha256`, `flakeLockSha256`, and
  `dependencyGraphSha256`. Hash the empty diff for a clean source tree; never omit
  the dirty-diff identity. Include tracked changes and added fixture sources.
- `shared.fixtureSha256`, `runnerSha256`, `analyzerSha256`, `referenceDataSha256`,
  `clientInventorySha256`, and `measurementConfigSha256`.
- `shared.os` (`name`, `version`, `arch`); `hardware` (`machineId`, `cpu`, `cores`,
  `memoryBytes`); `jvm` (`vendor`, `version`, `gc`, `flags`, `maxHeapBytes`);
  `database` (`engine`, `version`, `configSha256`); and `browsers`
  (`chromium`, `webkit` version strings).

`manifestSha256` is the SHA-256 of `JSON.stringify(parsedManifest)`, computed by
the exported `identity` function. This is sensitive to JSON key order; use the
checked-in file unchanged. Provenance and shared configuration must be identical
between comparison and calibration. Calibration still identifies the planned
candidate artifact, but **both sample variants execute the cell's baseline**.
Each sample's artifact hash is checked against that choice.

Each cell has three separate process passes: `latency`, `memory`, `operations`.
For **each** pass and mode require exactly 30 independent pairs, numbered 0–29.
The baseline runs first in even blocks and second in odd blocks. A sample has:

```text
kind: "sample"
cell, pass, block, variant, orderInBlock, processId, artifactSha256
completedWorkContractSha256, completedWorkVerified: true
warmupOperations, completedOperations, durationSeconds
profilingEnabled: true only for the memory pass
clockResolutionNs, measurementResolutionVerified: true
measuredResolutions: { each required metric for this pass: observed sensor resolution }
diagnostics: { jitCompilationMilliseconds, gcCount, gcMilliseconds }
metrics: { each required metric for this pass: measured number or null }
resources: { every required resource key: observed count }
counters: { every required operation counter key: observed value } // operations pass
```

`processId` is a globally unique collector-run identity, not a reusable OS PID.
It must differ across modes, cells, passes, blocks and variants. Resolution comes
from actual calibration probes; reporting the nominal clock unit is insufficient.
Unknown or unsupported measurements are `null`, never zero. Operations counters
are normalized per completed operation where their name says so; source/bundle
counts are absolute inventory totals. Resource values include peak/retained
metadata counts and final active-resource counts after complete release.

Validators verify the supplied protocol evidence. They cannot establish that a
collector actually executed work, measured a physical wire, found a true heap
peak, or correctly classified client source. Collector implementation, physical
correctness tests, raw profiles and review remain required.

## Decision rule

All 1,247 required metric/cell estimates belong to one declared family. Comparison
and calibration each produce an interval, so the Bonferroni tail is
`0.05 / (4 * 1247)`. The frozen 1,995,200 bootstrap replicates provide 20 draws per
adjusted tail. Changing the cell/metric family requires recalculating this value
and changing the manifest **before** candidate observations. Non-degenerate full
family analysis is computationally expensive; it has a two-hour cap and returns
inconclusive on timeout. Identical paired differences use the exact degenerate
bootstrap distribution without sampling.

For each metric, the estimator is the mean of the 30 paired, direction-adjusted
relative changes. If any baseline observation is zero, comparison and calibration
both use absolute paired differences in that metric's units. Higher throughput
is better. Latency quantiles are independent process-block quantiles; samples
from separate processes are never pooled to hide run-to-run variance.

The product slowdown allowance is zero. Pass requires an upper simultaneous bound
at or below zero for every metric. A positive lower bound is a regression; an
interval crossing zero or any missing metric is inconclusive. A/A must include
zero, have absolute mean relative drift ≤1%, and interval width ≤10%. For absolute
metrics, limits are one and four declared resolution units respectively. These
calibration limits govern evidence usability, not permitted product regression.

Warm latency passes require zero reported JIT compilation milliseconds. Cold
latency permits at most 10,000 ms compilation; all latency passes permit at most
5,000 ms GC time. Unsupported diagnostics or excess instability are inconclusive;
keep the raw records. Profiling in a latency/operations pass is rejected.

Every resource/operation ceiling must hold in both modes. Candidate operation
counts may not exceed the paired baseline even below the frozen ceiling. A
deterministic failure is reported as a regression even if a metric is missing.
No improvement in another cell or metric offsets that failure.

## Commands

Run from the repository through its flake:

```sh
nix develop --no-write-lock-file --command node --test \
  misc/browser-auth-baseline/performance/analyze.test.mjs \
  misc/browser-auth-baseline/performance/run.test.mjs
```

Inspect outstanding Phase 0 blockers (expected exit code 1 today):

```sh
nix develop --no-write-lock-file --command node \
  misc/browser-auth-baseline/performance/analyze.mjs \
  misc/browser-auth-baseline/performance/manifest.json
```

Analyze actual frozen evidence when available:

```sh
nix develop --no-write-lock-file --command node \
  misc/browser-auth-baseline/performance/analyze.mjs \
  misc/browser-auth-baseline/performance/manifest.json \
  comparison.jsonl calibration.jsonl report.json
```

The collection harness accepts explicit argument arrays for each source/pass;
it does not supply the missing workload collectors:

```sh
nix develop --no-write-lock-file --command node \
  misc/browser-auth-baseline/performance/run.mjs \
  misc/browser-auth-baseline/performance/manifest.json \
  collectors.json context.json NEW_OUTPUT.jsonl comparison
```

`collectors.json` maps `feature`, `historical`, and `candidate` to `latency`,
`memory`, and `operations` command arrays. `context.json` supplies the provenance
and shared metadata described above, including the actual runner/analyzer hashes.
Reserved collection identities are generated by the harness and cannot be
overridden by context. Each collector reads one request as JSON from stdin and
emits exactly one sample record. The request includes resolved metrics,
dimensions and work counts. Calibration selects the baseline command and
artifact for both labels.

Output and its `.processes.jsonl` raw companion must both be new paths. Collection
stops at its first failed observation, retaining earlier samples and a failure
marker. Each observation owns a Unix process group. Timeout kills the entire
group; a successful parent that leaves children behind also fails and triggers
cleanup. Collectors must not detach descendants into independent sessions. Each
stdout/stderr stream has a 16 MiB capture bound; exceeding it preserves the
captured prefix, marks truncation explicitly, kills the group and fails the run.
The async process monitor can kill descendants that inherited a pipe while the
parent has exited; it does not wait indefinitely for those pipes to close.

SIGINT/SIGTERM ownership cleanup is prepended ahead of previously registered
application listeners. It synchronously requests termination of every active
owned collector group before an older listener can call `process.exit()`.
Application listeners remain installed. Cooperative interruption drains raw
output, records incomplete evidence, and gives the CLI exit status 130/143.
An application's immediate exit can override that status and prevent raw-log
draining or a final failure record; existing samples then remain incomplete and
must not be accepted. SIGKILL, or a later listener deliberately prepended ahead
of ownership cleanup, cannot be covered by this ordering guarantee.

The synthetic unit fixtures test failure detection and statistics. They are never
performance observations of Spoonbill and cannot fill the reference's budgets.
